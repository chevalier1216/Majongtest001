# 青竹牌室 · Majongtest001

台灣十六張麻將單機遊戲，你對三位電腦。繁體中文、使用提供的原始牌面素材，不需外部 API。

試玩：[GitHub Pages](https://chevalier1216.github.io/Majongtest001/)

- 東風東局依序至北風北局；莊家胡或流局續莊，其他玩家胡則換莊並推進局次。北風北局莊家下莊後完成一將。

- 起始各 50,000 分。付款＝5,000 底＋500 × 台數；放銃者付，自摸三家付。涉及莊家的單筆付款加 1＋2×連莊次數台。
- 結算列出牌型台數、每筆莊台與算式，不把不同付款者的莊台混算。
- 電腦先決定是否吃碰槓胡，依優先序仲裁後，才展示真正可選的人類動作。胡 > 碰／槓 > 吃；一炮多響保留胡牌選項。
- 每次吃碰槓與補花、胡牌有 1.4 秒視覺提示，提示期間暫停出牌與 AI。
- 接牌時，「誰打出哪張牌」與吃／碰／槓／胡／過按鈕集中顯示在牌桌中央，不使用全桌遮罩。
- 四家補出的花牌以實際牌面放入各自公開牌區；暗手與公開牌分區顯示，吃碰槓沿各家的手牌方向連成一列，花牌另成平行的一列，公開牌區不使用拖曳捲動。四家花牌使用相同尺寸，保留各家明牌的朝向。
- 對家牌面朝下，上家朝右、下家朝左、本家朝上；上下家暗手維持單列，不再折成兩排。
- 吃後本次禁打吃入同牌與另一端替代牌：吃 1 成 123 禁 1、4；吃 6 成 456 禁 3、6。打出其他合法牌後解除。沒有合法後續出牌時不提供該吃法。玩家及 AI 同規則。
- 吃碰後不可在出牌前自行暗槓／加槓；須摸牌後才可。
- 上家打出的牌不可槓；其他方向的合法明槓仍可執行，規則層也會拒絕繞過介面的非法輸入。
- 以他人棄牌明槓後，第一次補牌即使成胡也不得胡；必須再完成一次未被搶槓胡的暗槓或加槓，才能以第二次補牌自摸。搶槓胡優先於槓家胡牌。
- 所有不能操作的牌維持可見，稍微降低飽和度及不透明度；合法手牌維持原樣，禁打由引擎再驗證。

## 本桌台數

以遊戲內「玩法說明」的完整台數表為準，程式唯一來源為 `dist/scoring.mjs` 的 `TAI_TABLE`。

採對位花與風刻：東春梅、南夏蘭、西秋竹、北冬菊。正花每張 1 台；四季或四君子齊全各 2 台，取代該組正花。圈風與門風可各計 1 台。

計入門清、自摸、門清自摸、三元刻、獨聽、平胡、全求人、三至五暗刻、碰碰胡、一色牌、大／小三元、大／小四喜、搶槓、海底／河底、槓上／花上自摸、天胡及地胡；多種合法拆法選最高台，互斥項目不重複。

八仙過海採「完成一般胡牌才加 8 台、取代花台」版本。宣告聽牌另加 1 台；本桌不採七搶一、天聽／地聽或包牌。一般槓後補牌可自摸；以棄牌明槓後則適用上述連續補槓限制。固定留 16 張，槓不加留。有人結算後低於零分立即結束本桌，先完成同次所有付款，再顯示最終點數排名；零分可繼續，同分並列名次。

桌規參考：[明星三缺一官方台數](https://www.gametower.com.tw/Games/Freeplay/MJ/Star31/Data/count.aspx)、[華人麻將競技聯盟](https://cml88.com/賽事規則/)。本桌明列的設定及使用者要求優先，不宣稱與任一平台完全相同。

## 操作與本機開發

點手牌選取，再按「打出」；雙擊直接出牌。左右鍵選牌、Enter 出牌。吃碰槓胡不設倒數。

以任意靜態 HTTP 伺服器提供 `dist/` 即可，例如 `python -m http.server 8080 --directory dist`。不是執行檔；依使用者指示暫停 Windows 打包。

無 npm 安裝、無 LLM、無雲端牌局計算；目前分頁保存分數，重新整理重開。首次成功載入並完成快取後可離線使用。

## 程式與驗證

- `dist/engine.mjs`：牌局、合法操作、AI、仲裁。
- `dist/scoring.mjs`：牌型拆解、台數與付款。
- `dist/app.mjs`、`dist/style.css`、`dist/responsive.css`：介面、動作提示、淡化及操作閘門。
- `dist/sw.js`：離線資源快取。
- `tests/engine.test.mjs`：基本規則及 30 局種子對打的 144 張牌／分數守恆。
- `tests/feedback.test.mjs`：風圈、台數、優先權與吃後禁打回歸。
- `tests/ui.test.mjs`：以 HTML 目標及受控時鐘執行實際介面程式，確認淡化、禁用及提示停頓；不是瀏覽器排版測試。

- `tests/table-flow.test.mjs`：骰子發牌、宣告聽牌鎖手與加台、負分終局及多人胡牌付款。
- `tests/layout.browser.mjs`：Chromium 檢查 1440×900、1024×768、844×390 的花牌尺寸／方向、五組副露加八張花、聽牌操作及排名畫面，並存下截圖。

執行 `node --test tests/*.test.mjs`（Node.js 20 以上）；GitHub Actions 通過規則與瀏覽器檢查後發布 Pages。

牌面 `dist/assets/tiles.png` 是使用者提供的原圖，以 CSS 顯示對應區域；未使用紅五。素材來源與授權未另行核實，不包含於程式碼 MIT 授權。

### 自適應介面

牌桌依視窗寬度調整，明牌保持可讀尺寸與連續排列；牌多時向下延伸，整頁可捲動，手牌不懸浮遮住明牌。手機橫向壓縮頁首，牌河各自可捲動。支援瀏海安全區、動態瀏覽器高度及可捲動的規則／結算視窗。直向手牌可橫向滑動；極低高度仍保留頁面捲動，避免隱藏牌與操作。


## 公開版與本機存檔（1.0.0）

正式網址：https://chevalier1216.github.io/Majongtest001/

外部玩家直接用瀏覽器開啟即可，不需要 Python、GPT、帳號或 API。遊戲每次有效操作後自動儲存完整牌局；再次開啟可選繼續或開始新遊戲。單局結算仍保留整桌進度，整桌結束清除續玩存檔。

存檔保存在同一裝置、同一瀏覽器；清除網站資料或使用無痕模式可能失去進度，不支援雲端或跨裝置同步。右上「存檔」可查看儲存狀態及版本；另一分頁更新時，舊分頁會暫停以避免覆蓋。

發布：`node scripts/build.mjs` 產出 `site/`，使用內容雜湊資源目錄，正式網址不需手動版本參數。main 的 Actions 先執行規則、排版及存檔瀏覽器測試，再部署 GitHub Pages。原始碼在 `dist/`。

## 推送與發布流程

首次設定工作環境：`node scripts/setup-dev.mjs`。這會安裝 Playwright 及 Chromium，並啟用推送前 hook。每次推送前必須通過 `node scripts/preflight.mjs`，包含規則、正式建置、畫面、續玩與離線測試。失敗留在本機修正，不推送試錯。

在 `fix/*`、`feature/*` 或 `work/*` 分支完成修改，通過本機檢查後推送，等待分支的 `verify` 成功，再將同一個已驗證提交快轉至 main。Actions 將驗證與部署分為不同工作：分支只驗證；main 驗證成功才部署同一份建置產物。API 推送也必須遵守 AGENTS.md，不能以 API 略過本機驗證。

GitHub 真正的測試／部署失敗仍如實顯示並依個人通知設定寄送；此流程減少未驗證提交造成的通知，不隱藏錯誤或停用通知。
